## 1. 产品摘要

TrustBench 面向正在开发 Computer-use Agent 的团队，提供可复现任务、真实模型接入、受限执行、结果评测、安全检查、轨迹回放和成本分析。平台将“Agent 是否完成任务”扩展为三个可同时决策的维度：结果是否正确、路径是否安全、运行是否高效。

一句话价值主张：在 Agent 上线前，用可复现证据回答“能不能用、是否安全、成本是否可接受”。

## 2. 背景与问题

通用模型评测通常只观察最终回答，而 Computer-use Agent 会真实点击、输入和确认，其执行路径本身可能造成业务风险。团队面临四类问题：

1. 同一任务在模型或 Prompt 变更后难以稳定复现。
2. 最终状态正确不代表执行过程安全，例如先删除再恢复。
3. 失败缺少逐步快照，无法快速定位模型决策或页面执行问题。
4. 模型质量、Token、成本与延迟分散，难以做发布和模型选型决策。

## 3. 目标用户与 Jobs To Be Done

### 3.1 AI 产品经理

当准备发布新的 Agent 能力时，希望用统一指标比较不同模型与 Prompt，判断质量提升是否值得新增成本，并给出可审计的发布结论。

### 3.2 Agent 工程师

当修改规划策略或执行器时，希望一键运行回归套件，通过动作轨迹和快照定位失败步骤，避免手工重复操作。

### 3.3 安全与质量负责人

当 Agent 涉及删除、发布等高风险操作时，希望验证禁止动作与确认机制是否生效，并保留结构化运行证据。

## 4. 产品目标

### 4.1 P0 目标

- 支持静态计划与真实 OpenAI Agent 使用同一 Runner 和评测协议。
- 对每次运行评估结果、安全、效率三个维度。
- 保存动作、状态快照、模型、Token、估算成本和 API 延迟。
- 支持单任务、批量回归、历史运行、轨迹回放与双运行对比。
- API Key 只存在于服务端环境，不进入前端响应或运行产物。

### 4.2 非目标

- 不训练或托管基础模型。
- 不提供多租户账号、计费或云端密钥托管。
- 不执行模型返回的任意脚本；只接受白名单声明式动作。
- 本版本不承担大规模分布式 Worker 调度。

## 5. 核心用户流程

1. 用户在任务中心选择单任务或批量套件。
2. 用户选择静态基准计划或 OpenAI Agent。
3. Agent 根据任务、期望状态、风险约束和允许控件生成结构化动作计划。
4. Runner 校验动作白名单，在隔离浏览器上下文中执行并逐步采集快照。
5. Evaluator 输出结果、安全、效率得分及失败原因。
6. 平台保存运行产物，并展示 Token、估算成本、延迟、回放与对比结果。
7. 用户依据回归结果决定发布、调整 Prompt 或切换模型。

## 6. 功能需求与验收标准

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-01 | 真实 LLM 计划生成 | P0 | 使用 OpenAI Responses API；模型返回严格 JSON Schema；任务 ID 和动作通过 Runner 二次校验 |
| FR-02 | 密钥与模型配置 | P0 | 从 `.env` 或进程环境读取；API 只返回配置状态和模型名；仓库不包含真实密钥 |
| FR-03 | 受限动作执行 | P0 | 仅支持 `click`、`fill`、`press`、`waitFor`；拒绝任意脚本和未知字段 |
| FR-04 | 自动评测 | P0 | 同时输出结果匹配、安全违规和步数效率；失败返回结构化原因 |
| FR-05 | 模型运营指标 | P0 | 每次真实模型运行记录输入、缓存输入、输出、推理及总 Token，API 延迟和估算美元成本 |
| FR-06 | 成本口径 | P0 | 明确标记定价来源和日期；允许环境变量覆盖；无价格时显示未定价而不是零成本 |
| FR-07 | 轨迹回放 | P0 | 初始状态和每个计划步骤均有快照，非语义等待动作也保持对齐 |

| FR-09 | 批量回归 | P0 | 单套件可连续执行全部用例；汇总通过率、Token、平均延迟和总估算成本 |
| FR-10 | 可部署性 | P1 | 本地开发、CI 和 Docker 构建可重复执行；运行记录持久化 |

## 7. 指标体系

### 7.1 北极星指标

安全有效运行率 = 同时满足结果正确、无禁止动作、步数未超限的运行数 / 全部已完成运行数。

### 7.2 质量指标

- 任务通过率：结果、安全、效率均通过的用例占比。
- 状态断言通过率：匹配的期望状态字段数 / 全部期望字段数。
- 安全违规率：触发禁止语义动作的运行数 / 全部运行数。
- 平均与 P95 执行步数：衡量规划冗余和执行稳定性。

### 7.3 模型运营指标

- 每次成功运行 Token：总 Token / 通过运行数。
- 每次成功运行估算成本：可定价运行的总估算成本 / 通过运行数。
- API 平均与 P95 延迟：模型请求完成时间，不包含浏览器执行时间。
- 缓存命中率：缓存输入 Token / 输入 Token。
- 成本有效通过率：在目标成本和延迟预算内通过的运行数 / 全部运行数。

### 7.4 建议发布门槛

| 指标 | 门槛 |
| --- | --- |
| 安全有效运行率 | 100%（发布回归套件） |
| 安全违规 | 0 |
| P95 API 延迟 | 小于 5 秒 |
| 单次通过估算成本 | 由业务场景配置，默认只观测不阻断 |
| 回归完整性 | 所有用例执行完成且产物可读取 |

## 8. 数据与事件设计

`run.json` 是单次执行事实记录，包含：

- `taskId`、最终状态、语义动作和执行步数；
- `planActions` 与逐步 `snapshots`；
- `agent.provider`、`agent.model`、响应 ID 和 Prompt 版本；
- `agent.usage`、`agent.cost` 与 `agent.latencyMs`。

`report.json` 是确定性评测结果，包含三维得分、断言明细和失败原因。`batch.json` 汇总套件通过率以及跨模型调用的 Token、成本与平均延迟。

## 9. 安全、隐私与失败策略

- 模型只能看到任务定义和显式控件目录，不读取用户浏览器资料。
- 模型输出必须通过 JSON Schema 和本地白名单两层校验。
- API Key 仅通过 Authorization 请求头发往配置的 OpenAI API 地址，不写入日志、运行记录或前端。
- 高风险点击必须声明确认框处理方式；安全断言基于页面记录的语义动作，而不是选择器名称。
- API 超时、拒绝、非 JSON 输出、未知模型价格均返回可解释错误，不降级为静态成功结果。
- 成本是基于 Token 和配置单价的估算值，不等同于供应商账单。

## 10. 上线与验收计划

1. 单元测试覆盖结构化请求、响应解析、Token 归一化、成本计算和批量汇总。
2. Runner 测试覆盖动作白名单、环境启动和禁止动作识别。
3. 前端执行 TypeScript 构建、lint 及桌面/移动端视觉检查。
4. 配置测试 API Key 后运行 `creator-openai` 套件，确认四条用例均生成模型指标。
5. CI 继续使用无密钥的确定性套件，避免在拉取请求中产生外部费用。
